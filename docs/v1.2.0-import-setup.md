# v1.2.0 — import and configuration

This is an interactive educational Automation Anywhere 360 (AA360) Community Edition bot. The sanitised ZIP was imported as a separate bot and produced a verified 582-record full-dataset CSV after the user configured the external JSON file location.

1. Import `release/NHL_Hockey_Data_Collector_v1.2.0_AA360.zip` through your AA360 Control Room. Keep prior versions and your working bot separate.
2. Copy [config.example.json](../config.example.json) to a local `config.json`. Create a writable `output.directory`; Windows backslashes must be doubled in JSON strings.
3. In the imported bot, point the File variable `fConfigFile` to the real config file. Its packaged default `file:///C:/Automation/NHL_Hockey_Data_Collector/config.json` is a **placeholder** and will not automatically find a file. The unused `sConfigPath` variable also contains a generic example.
4. Check Chrome, AA360 Bot Agent and Recorder/browser extension support. Run manually without interacting with the browser.
5. Start with `max_page_attempts=3` for a controlled two-page run; expect **PARTIAL RUN**, 50 records and a reminder that more pages remain. Restore `30` for the full run if appropriate to the demo site's published rules.

The bot tries to navigate a matching existing Chrome tab to the source URL. If AA360 reports an error containing `Unable to find`, it opens a new Chrome window instead. It checks the actual URL before collection, and stops if it differs from the configured URL. This fallback relies on AA360 error-message wording and has only been validated in the author's tested environment.

## Run outcomes

- **COMPLETED**: pagination reports no further Next link, and both final CSV write actions returned without throwing an error.
- **PARTIAL RUN**: a further Next link remains when the configured attempt cap is reached; exported CSV can be incomplete.
- **FAILED**: caught exceptions in JSON loading, numeric conversion, browser initialisation, main pagination or final CSV export display the exception and failing action number, then stop the bot.

Completion does **not** independently prove that every source-site record was captured, nor does it verify file contents after writing. If a second final export fails, the first file may have been updated and the other left stale. The intermediate working CSV can also change before an error.

`source.next_link_xpath` is included in the JSON example but is **not wired into** the Recorder's Next selector. The bot remains interactive, without structured persistent logging or automatic retries. A missing/broken Recorder object may invoke AA360's own native fallback before an exception can be caught. Not intended for unattended operation.
