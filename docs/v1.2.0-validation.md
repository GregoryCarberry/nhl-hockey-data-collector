# v1.2.0 — validation and remaining limitations

Tested 17 November 2026 with Automation Anywhere 360 Community Edition. Tests below are user-operated AA360 runs with independent Google Drive CSV readback where specified, not automated cross-platform qualification.

## Scoped failure tests

| Area | Controlled input / scenario | Observed |
| --- | --- | --- |
| Configuration load | Nonexistent JSON file URI | Caught; displayed unresolved file path and failing action 2; Stop |
| Numeric conversion | `scraping.max_page_attempts` set to `"INVALID_TEST"` | Caught input conversion error, action 15 |
| Browser existing tab | Previously paginated tab at `?page_num=24` | Reopened base page; full output regression passed |
| Browser missing tab | No matching page open | Existing-tab attempt failed; Catch opened new Chrome window; full output regression passed |
| Starting URL mismatch | Browser reference resolved to stale page 24 | URL mismatch check displayed expected vs actual URL and stopped |
| Final export | Consolidated destination set to nonexistent `Z:` directory | Caught line 89; diagnostic file updated but consolidated file remained stale |
| Pagination loop | Intermediate working CSV destination set to nonexistent `Z:` directory | Caught line 71; one page attempted, zero unique pages; final exports not attempted |
| Partial result | `max_page_attempts=3` | Reported PARTIAL RUN, 3 attempts, 2 unique pages, Next available; 50 rows verified |
| Completed result | `max_page_attempts=30` | Reported COMPLETED, 25 attempts, 24 unique pages, Next unavailable; 582 rows verified |

A test with deliberately invalid Recorder table selectors did **not** reach the pagination Catch: AA360 offered its native Recorder fallback. That test was stopped and selectors were restored.

## Full-dataset checks

After reverting each temporary test change, fresh consolidated files were compared with retained first-page (25 rows) and second-page (25 rows) reference data and the last-page diagnostic. Across the successful full regressions the output contained **582 records**, each with nine CSV columns, no blank rows and no identical duplicate rows. The final seven records matched the seven-row diagnostic; the range was Boston Bruins 1990 through Winnipeg Jets 2011.

**Independent package import:** A separate copy of the sanitised v1.2.0 ZIP was successfully imported to AA360 and its `fConfigFile` changed to the working external config path. The user's imported-bot run generated both files, independently read back in Drive on **17 November 2026 at 08:39 UTC**, matching the same 582-record reference. This is stronger than static ZIP validation but is not proof of another machine's environment.

## Known limitations

- No persistent structured log, retries, or unattended operation; interactive messages still require acknowledgement.
- Browser tab targeting uses a recorded Window variable, and missing-tab fallback inspects the human-readable AA360 message `Unable to find`. Other matching-window ambiguity and error variants remain possible.
- An apparent natural end does not guarantee all historical records; a v1.1.0 run once produced only 532 rows. The stale-window hypothesis has supporting reproduction in v1.2.0 but is not proven as the historical root cause.
- CSV writes are sequential, not atomic; one can succeed while the other fails.
- Completeness is compared with a historical 582-row reference snapshot, not a permanent guarantee that the source site still contains that total.
- Pre-navigation delay is not HTTP-level measurement or proof of website-rule compliance; `source.next_link_xpath` is not operational.
